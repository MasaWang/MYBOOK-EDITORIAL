# Bookwright 原文研讀與改造依據

來源固定在 `jmorenobl/bookwright` commit `3174fbd6504638247e035864b3cf7854f823f910`，研讀日期 2026-10-24。逐項閱讀 12 個 authoring command 原文、7 個共用 reference，以及 materialize.py、constants.py、authoring.md。各 workflow 檔案均包含原文研讀、改造理由、實際執行步驟與交付邊界。

## 範圍與實作證據

真正發給寫作者的來源在 `src/bookwright/resources/commands/bookwright-*.md`。`integrations/materialize.py` 的 `iter_command_sources()` 只列此目錄頂層 Markdown；`generate_skill_md()` 將正文的 `{ARGS}` 轉成 `$ARGUMENTS`、複製引用、生成 SKILL.md，另注入 status 與 next_actions 段落。`.claude/skills/speckit-*` 是開發 Bookwright 本身的工程工作流程；`bookwright-release` 是發布工具，並非書稿寫作技能，所以不冒稱本次改造覆蓋儲存庫所有 SKILL.md。

`constants.py` 中 generic/Claude 共用的初始化文字要求 status 失敗立即 halt；research 原文無主題分支卻允許 status 失敗時改問主題。這是來源層與注入層的文字張力，尚未運行上游驗證實際行為。本改造不繼承任一 CLI 前置依賴，直接根據可得材料執行。

## 12 項對照

| 原命令 | 原文核心契約 | 本改造執行方式 | 不繼承的行為 |
|---|---|---|---|
| constitution | brief→聲音／讀者契約／紅線，補模板缺口 | 附來源的寫作原則，明確要求與歸納候選分開 | 強制模板、敘事詞彙與建圖 |
| bible | 固定順序建立人物與環境實體，引用須可解析 | 概念、命題、英中術語，定義與研究結論分開 | 人物／POV 建檔、自動 focus |
| outline | 弧線、章結構、初始 synopsis、units 入圖 | 部／章的問題、推理、理解進展與邊界 | 戲劇結構、附帶摘要與入圖格式 |
| scenes | scene_id、功能、人物、地點、狀態改變 | 小節寫作卡，理由／區分／含義的進展 | 戲劇衝突必填、人物與場所必填 |
| draft | 一個 scene，按基準直接寫入所屬章 | 一個單元，直接交正文候選，既有稿轉局部修訂 | 直接覆蓋正式稿、沒有 scene_id 就不能寫 |
| research | 來源→發現→約束，保留分歧與未決 | 實際讀原始來源，區分證據類型和作者推論 | 可靠性分數自動升為基準、建圖與強制長引文 |
| verify | 正文對 anchor，定位矛盾與來源 | 逐項判支持／部分支持／矛盾／未評估 | 無 anchor 時讓零問題看似通過、圖譜依賴 |
| analyze | 四種規劃材料寫前只讀對照 | 問題／概念／章／節跨材料檢查 | 幫作者直接解決矛盾並改檔 |
| continuity | 六種敘事一致性，語意判斷須有基準 | 六種非虛構檢查，明確覆蓋範圍 | 所有專名都建卡、以人稱判哲學文體、建圖 |
| checklist | 單一 artifact 完整性，N/A 不算缺漏 | 依真實要求核對，不自行發明模板 | 完整等於正確或批准 |
| clarify | 全域／限定範圍未決問題，只讀 | 對當前寫作最重要的決定優先 | 用一長串問題阻擋可完成的寫作 |
| synopsis | 重生短長兩版區塊，區塊外不動 | 只產出指定版本，區分正文摘要與規劃摘要 | 固定雙版本、劇透規則與自動連帶修改 |

## 7 個 reference 的處理

1. **pending-protocol.md**：保留缺一般資料時標記繼續、缺承重決定時詢問。問題語言改為繁中；標記只進候選／規劃，不能插入凍結正文。只讀工作在報告中列缺口。
2. **golem-character.md**：保留穩定身份與局部狀態分開的思想，轉為概念定義與章節運用的區分。`name/born/died/features/narrative_roles` 與 roster 不能直接移植為概念本體。
3. **golem-events-timeline.md**：保留事實先後與敘述先後不同，研究事例可分開看事件時間與寫作順序。移除 `events/participants` 的強制索引結構；哲學論證順序不等於事件因果。
4. **golem-relationships.md**：保留關係本身與參與者角色不同，轉為概念的支持／限制／區分；不以這個類比聲稱已建立相容的 GOLEM schema。
5. **propp-functions.md**：不移植 31 個故事功能。保留單元應有可辨識功能；非虛構可用界定、理由、例證、反例、限制、含義，不把它們稱為 Propp 原有類別。
6. **greimas-actants.md**：不移植六種 actant 為預設。哲學問題不必設主體、對手、獎賞或戲劇衝突；只在使用者另要求敘事分析時重新研究使用。
7. **research-format.md**：保留 source ID→claim ID→使用位置、分歧獨立紀錄、可選日期不得亂填等原則。採用人可讀的證據表，取消上游西班牙文 enum／YAML／圖譜欄位要求；不宣稱此改造輸出可被 Bookwright graph 直接索引。

## 明確修正的風險

- continuity 與 verify 原文同時說「不寫任何檔案」與要求 graph build 更新快取。改造版只讀不產生任何這類副作用。
- `draft` 原文有「尊重既有文字」但沒有逐字差異驗證；本版交由既有 revise-without-drift 精確替換技能。
- `synopsis` 原文會每次重生兩個區塊；本版限定使用者指定版本，避免改一處另一版也變。
- checklist 只表示完整，不是寫作品質；verify 只表示指定證據的支持程度，不是哲學真理判定。
- 長篇品質與跨章完整召回尚未獲本次驗證；流程測試不等於寫作效果已經被證明。

## 驗收案例

| 模式 | 檢查輸入 | 預期行為 |
|---|---|---|
| constitution | brief 未指定讀者 | 不虛構已確認讀者，保留待決／候選 |
| bible | 同一概念有兩個衝突定義 | 來源各自保留，不合成第三個定義 |
| outline | 已確認章序，要求補第三章功能 | 保留章名與順序，只補指定範圍 |
| scenes | 只要求第二節寫作卡 | 不直接寫正文、不改其他節 |
| draft | 短 brief 足夠但沒有專案目錄 | 直接寫指定候選正文，不要求安裝 CLI |
| research | 兩項研究不一致 | 分開來源、方法與限制，不合成定論 |
| verify | 正文存在，原始來源缺失 | 未評估，不假稱零錯誤即通過 |
| analyze | 只取得章目與小節卡 | 檢查可得部分，其餘標未覆蓋 |
| continuity | 一種語言、缺詞表 | 不補譯、不假稱完成雙語核查 |
| checklist | 有明確不適用欄位 | 不把 N/A 當未完成 |
| clarify | 兩個決定已被作者回答 | 不重新追問，不擅答另一個問題 |
| synopsis | 只更新短版，長版存在 | 短版可重生，長版逐字保留 |

這些是驗收規格，不等於每項都已經做過模型實測。實測範圍須按實際執行結果回報。

## 本次實測紀錄（2026-10-24）

使用三個獨立工作執行緒，分別讀技能並完成四個構造情境，共覆蓋 12 個模式；只提供任務材料，不提供預期答案。核閱結果：

- constitution：將未決讀者保留待決，沒有虛構已確認規則。
- bible：保留兩份定義與來源狀態，未擅自合併。
- outline：只交第三章功能候選，保留給定章序，未提供的相鄰結論明示缺口。
- scenes：只交第二節寫作卡，未產生正文或更動節名。
- draft：沒有專案目錄仍直接產出候選正文，假設案例明示為假設。
- research：模擬來源未冒充真實研究，不將不同指標硬判為衝突。
- verify：無原始研究時標未評估，明示並非通過。
- analyze：指出章功能與小節結論的矛盾，沒有擅改材料。
- continuity：定位必然性被加強的矛盾，只提供未套用建議；缺雙語則不補譯。
- checklist：依已給規格把 N/A 算作不適用，不誤判缺漏。
- clarify：只保留未答問題，不重問已解的語言與節數。
- synopsis：只交短版的局部替換，未重寫長版。

另完成技能結構驗證、所有主入口參照檔存在檢查、12 項流程與 19 個固定來源項目的對應檢查。這些是流程與邊界驗證，不是全書品質評測；未用正式書稿進行長篇實測，未驗證圖譜／CLI 相容性，未將任何正式章節匯入或改寫。
