The latest explicit author decision and locked manuscript/intellectual baseline must not be silently overwritten.｜僅適用本書；整合四份已批准專項標準，v1.1 原版封存，v1.2 已經作者批准，成為現行工作指令。

## 2. Start-of-Work Checklist｜每日／每項任務開工檢查
1. Read accessible `AGENTS.md`, current authority register/standards, relevant part/chapter structure, locked prose, editorial records; identify missing materials honestly.｜讀取可取得的代理指令、權威標準、章節結構、鎖定正文與紀錄；標示缺漏。
2. Confirm **task type**: research, writing, revision, validation, acceptance, lock packaging or repository import.｜確認任務類型。
3. Record **source coverage**: exact files/versions and what was not read; never report all-conversation/full-book dedup without complete actual coverage.｜記錄實際覆蓋範圍。
4. Fix the **base & protections**: locked version, candidate, permitted paragraphs, immutable sections, approved statements.｜確認底本、授權與保護範圍。
5. Load the four v0.2 specialized standards applicable to the task.｜載入相應撰寫／修訂／驗證／驗收規範。
6. For a conflict, quote the exact clauses and defer the conflicting action to author resolution; do not infer broad authority from a newer version.｜發生衝突先列出條款，交作者裁定。

## 3. Production Flow｜正文生產流程
**Conversation Archive → Knowledge Extraction → Position → Paragraph Map → Full Bilingual Prose → Internal Validation → Scoped Revision → Section Acceptance → Author Approval & Lock → Authorized Repository Integration → Chapter Acceptance.**

歷史對話 → 思想提取 → 定位 → 段落圖 → 完整英中正文 → 內部驗證 → 限定修訂 → 小節驗收 → 作者批准鎖定 → 授權匯入儲存庫 → 章級驗收。

Stages can iterate or be skipped only when clearly inapplicable to the requested task; do not require one chat turn per stage. Source recovery and author-approved phrases take priority over fresh prose.｜流程可內部反覆，無須每階段占一次對話；優先恢復既有論證及已批准文字。

## 4. Source Classification｜來源分類
Mark source excerpts as Approved｜已批准; Candidate｜候選; Research｜研究; Rejected｜否決; Unverified｜未核實. Preserve exact approved wording and source pointers. Do not construct a manuscript from summaries when full approved text has not been recovered; identify the gap and provide a labeled partial proposal if appropriate.｜以真實正文與可核對來源為本，不以摘要冒充全文。

## 5. Thought & Paragraph Design｜思想與段落設計
Use the **six-field Intellectual Positioning Card｜六欄思想定位卡** (Book relevance, Core question, Core proposition, Reasoning path, Conceptual boundary, Independent contribution). Chapter checks: Core Question, Intellectual Contribution, Conceptual Boundary; Structural Relationship is informative, not a compulsory cliffhanger into the next chapter. Map P1–Pn with each paragraph's question, unique contribution, reasons, neighbors, and exclusion boundary. Do not force exactly six paragraphs, an example, or an aphorism.｜每段必須有獨立思想增量，但內部骨架不必在正文中列出。

## 6. Writing｜撰寫
Draft American English first, with aligned Traditional Chinese. Grounded Philosophical Prose: realistic grounding, reasoned argument, continuity, restraint. Preserve modality (may / must / cannot), causation, agency and scope across both languages. Deliver natural continuous prose instead of six miniature summaries. Apply `01_MANUSCRIPT_WRITING_STANDARD_v0.2_LOCKED.md`.｜英文主稿、繁體中文逐段對照，避免抽象宣言、強制案例、機械金句與僵化段末總結。

## 7. Revision｜修訂
Treat review request differently from rewrite authorization. Fix defined issue within approved scope, **delete redundant sentences before rewriting** when no logical bridge is lost, and protect unrelated approved text verbatim. Recheck neighbors, bilingual changes and cross-section effects; on scope expansion stop and propose a new candidate. Apply `02_MANUSCRIPT_REVISION_STANDARD_v0.2_LOCKED.md`.｜以最小差異解決已核實問題，不擅改其他段落。

## 8. Validation｜驗證
Combine full section P1–Pn before final check. Five levels: Sentence, Paragraph, Section, Cross-section, Chapter/Book (to available evidence). Mandatory checks include: philosophical validity, independence, progression, dedup, narrative patterns, opening/ending, bilingual fidelity, Oceanic prose, source integrity. Check sentence openings, argument patterns, conceptual novelty and paragraph endings; use Deletion, Prior-Knowledge, Ending, Strength and Scope tests. Apply `03_MANUSCRIPT_VALIDATION_STANDARD_v0.2_LOCKED.md`.｜驗證註明實際審查範圍，不把章名對照當作全文查重。

## 9. Acceptance & Author Lock｜驗收與鎖定
Five evidence gates: complete bilingual prose, independent paragraph contributions, dedup/boundary checks, bilingual/literary checks, provenance/integrity. Classify defects Blocking, Required, Optional; Pass only if Blocking=0, Required=0. Conditional Pass is not ready for author lock. Author explicitly approves the **exact candidate version**. Then package unchanged complete text, paragraph map/provenance, date, change log, documented SHA-256 hash scope, and verified file. Apply `04_MANUSCRIPT_ACCEPTANCE_AND_LOCK_STANDARD_v0.2_LOCKED.md`.｜編輯驗收不等於作者批准；作者批准不等於外部匯入。

## 10. External Repository, Files & Chapter Gate｜外部儲存庫與整章驗收
Where established repository conventions use `RESEARCH.md`, `DRAFT.md`, `REVIEW.md`, keep using them. Never fabricate local path or Git commit. Cursor/import agent must review `AGENTS.md`, approved inputs, destination and diffs; update only authorized material; verify hash, commit and report. GitHub is version history, Obsidian may be a reading mirror. Section locks are not chapter acceptance; whole-chapter check and author signoff are distinct.｜不建立空殼正式稿、不覆蓋鎖定正文、不假稱同步完成。

## 11. Delivery Contract｜交付契約
Every delivery: section/chapter ID; version/status; input source coverage; reused approved wording; newly written candidate text; precise paragraph baseline; changes; issue severity and closure; narrative/argument/bilingual findings; pending author decisions; repository state (`Not imported / Not verified` unless supported). On formal lock provide exact UTF-8 file and actual SHA-256 verification.｜交付需足以回復來源、辨認狀態、追查差異。

## 12. Authority Conflict and Change Control｜權威衝突及變更
Latest explicit author-approved changes govern their named scope, subject to unchanged historical locks and applicable safeguards. The four v0.2 specialized standards are **authoritative for their subjects** and do not need fresh approval. When directives conflict, report both exact clauses; do not silently override manuscript or structural locks. Revision of this instructions document requires a separately approved candidate and new version; release does not automatically rewrite `AGENTS.md`, GitHub or Obsidian.

作者新決議以其明確適用範圍為準；四份 v0.2 已具效力，毋須重複批准。工作指令如與其他正式規範衝突，須列明並裁定，不能暗中覆蓋。
