# Manuscript Validation Standard｜書稿驗證標準

**Project｜專案：** 《智慧之海》｜The Ocean of Wisdom  
**Version｜版本：** v0.2  
**Status｜狀態：** Candidate — Author Approval Required｜升級候選，尚待作者批准  
**Date｜日期：** 2026-10-15  
**Evidence｜修訂依據：** 3.1 Locked v1.1、3.2 Locked v1.0、3.3 Locked v1.0 的撰寫及修訂歷程，與既有 EDITORIAL_STANDARD v0.1 LOCKED、Manuscript Production Instructions v1.1。  
**Protection｜保護聲明：** 本套標準僅為新增候選，不修改、撤銷或取代上述鎖定基準。  

## 1. Objective｜目標
Find problems and establish evidence; validation is not author approval. Validate a complete section after merging paragraph versions, even when individual changes were checked separately.

驗證目的在於發現問題並留下可核實依據；局部修訂通過不等於整節通過，整節通過不等於作者批准。

## 2. Five Validation Layers｜五層驗證
| Layer｜層級 | Question｜問題 | Evidence｜證據 |
|---|---|---|
| Sentence｜句子 | 語義、情態、因果是否精確？ | 原句與修訂句 |
| Paragraph｜段落 | 有不可替代的思想增量？ | 段落功能與刪除測試 |
| Section｜整節 | 推理是否連續且首尾有增量？ | P1–Pn 論證圖 |
| Cross-section｜跨節 | 是否重複已鎖定認識或搶先後節？ | 對照命題與來源 |
| Chapter/Book｜章／全書 | 是否侵犯章級及全書結構？ | 已取得的基準及覆蓋範圍 |

## 3. Mandatory Checks｜必須檢查的九項
1. **Philosophical Validity｜哲學成立性**：主張、推理與限定是否相符。
2. **Paragraph Independence｜段落獨立性**：每段問題／思想增量／刪除後損失明確。
3. **Argument Progression｜論證遞進**：前後段確有認識增量。
4. **Argument Deduplication｜論證去重**：同義反覆（即使換詞）均需辨認。
5. **Narrative Pattern Review｜敘事模式**：句首、對照論證、概念新意、段末節奏。
6. **Opening–Ending Balance｜首尾平衡**：開篇不先宣布全部結論，收束不簡單重述開篇。
7. **Bilingual Semantic Fidelity｜英中語義一致**：情態詞、量詞、因果、概念、節奏。
8. **Oceanic Prose Quality｜海海風**：扎根現實、論證充分、自然連續、克制、不強制案例／金句。
9. **Version & Source Integrity｜版本來源完整性**：明確每段來源；沒讀到的來源不假裝查過。

## 4. Diagnostic Questions｜診斷測試
**Deletion Test｜刪除測試：** 移除該句／段，獨立推論是否消失？如無損失，優先考慮刪除。

**Prior-Knowledge Test｜前文已知測試：** 讀者是否已從先前鎖定小節獲得同一認識？如果是，本節須產生新推進。

**Ending Test｜段末測試：** 最後一句是新發現、必要轉折，還是重複性解說？不要強制每段有總結句。

**Strength Test｜強度測試：** 英文 must/cannot 與中文「必須／不能」是否比證據更強？

**Scope Test｜邊界測試：** 是否偷渡後節的系統後果、倫理判斷或整章總結？

## 5. Severity and Findings｜問題分級
- **Blocking｜阻斷：** 核心論證錯誤、重大跨節重複、未授權變更、英中反義或正文不完整。
- **Required｜必修：** 局部冗餘、概念不精確、論證斷裂、英中語義強度差異。
- **Optional｜可選：** 不影響理解的文學風格偏好。不得因可選事項阻止已合格稿件驗收。

Each finding states location, exact evidence, why it matters, smallest effective fix, scope authorization, and recheck outcome.

每個問題需有位置、原句證據、影響、最小解法、授權範圍與複驗結果，避免只有「不夠好」的主觀評語。

## 6. Evidence Boundaries｜驗證證據邊界
Use actually available locked files, source archives and metadata. State whether checking was section-local, adjacent-section, chapter, or full-book. A chapter-title map is not equivalent to reading full chapter prose; no unperformed full-book deduplication claims.

明示審查覆蓋範圍；只有章名／功能基準時，不得宣稱完成全部正文的逐字查重。

## 7. Output Format｜驗證報告八欄
`Identity｜識別 → Core Proposition｜核心命題 → Paragraph Baseline｜段落基準 → Argument Map｜論證路徑 → Findings & Evidence｜問題與證據 → Narrative/Bilingual Review｜敘事與雙語 → Remaining Issues｜遺留 → Validation Result｜驗證結果`。

Validation result must distinguish: all mandatory checks passed; conditional with precise unclosed issues; or failed. Then pass the file to **separate** acceptance, not directly to Locked.
